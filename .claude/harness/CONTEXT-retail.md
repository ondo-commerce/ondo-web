# 온도 하네스 공통 브리핑 — 소매(온도 마켓 / On도마켓)

3단계(PM · FE · Verify)가 **소매 회차 시작 전 반드시 읽는** 문서다.
도매(`apps/wholesale`) 작업은 이 문서가 아니라 `CONTEXT.md`를 읽는다. **둘을 섞지 않는다.**
에이전트끼리는 대화하지 않는다. 주고받는 것은 실행 디렉터리의 파일뿐이다.

## 2. 레포

**구조·커밋·브랜치·import 방향·색 토큰·`packages/ui` 읽기 전용은 `~/onDo/CLAUDE.md` 에 있다.**
세션마다 자동으로 읽히므로 여기 다시 적지 않는다.

이 회차에만 해당하는 것:

- 앱: `apps/retail` · 커밋 스코프 **`feat(retail):`** · dev `pnpm --filter retail dev`
- **선례: `apps/wholesale/src/features/product/`** — 폴더 구성·주석 밀도·네이밍의 기준이다.
  `apps/wholesale` 은 읽기만 한다 (훅이 쓰기를 막는다).

## 3. 절대 규칙

2. **소매 셸은 상단 GNB 1줄이다.**
   ⚠️ 사양 문서(`retail_screen_spec.md` §0)는 "도매는 좌측 사이드바라 구조가 정반대"라고 적었지만
   **코드는 다르다** — 도매도 사이드바를 폐기하고 상단 헤더로 갔다(`apps/wholesale/.../Topbar.tsx` 주석).
   그러니 "정반대"가 아니라 **헤더의 내용물이 다른 것**이다.
   도매 헤더 = 주 메뉴 7탭. 소매 헤더 = 통합 검색 + 찜·장바구니 + 계정 드롭다운(메뉴는 드롭다운 안에).
   도매 `Topbar`·`AppShell`을 **복사하지 않는다** — 저쪽은 `h-dvh` 고정 전제라 소매의 문서형 스크롤과 맞지 않는다.
3. **소매는 세로로 스크롤되는 페이지다.** 도매의 "화면 전체 스크롤 없음 / `Panel`이 유일한 표면"
   두 규칙은 **소매에 적용하지 않는다.** 상품 그리드·상세·주문서는 문서처럼 아래로 흐른다.
   대신 **헤더는 늘 같은 자리**에 있고, 장바구니·주문서의 합계 바는 화면 하단에 고정된다.
4. **Rule of Two.** 새 패턴은 처음 쓰는 화면 **안에** 둔다. 사용처가 2곳이 되는 PR에서 `shared/`로,
   도매에서도 쓰이면 그때 `packages/ui`로 올린다. 소매 한 곳만 쓰는 컴포넌트를 `packages/ui`에 만들지 않는다.
7. **더미 데이터는 `fixtures.ts`에.** 컴포넌트 안에 데이터를 적지 않는다. API는 아직 없다.
8. 주석은 **왜**를 적는다. 무엇은 코드에 있다. 한국어.
9. **소매는 금액을 쓰지만 돈을 움직이지 않는다.** 입금 등록 권한이 없고(RT-63), 결제 수단은
   `현금`/`계좌 이체` **안내**뿐이다(게이트 D2). 결제 UI를 지어내지 않는다.

## 5. 소매 셸 (전 화면 공통 · `retail_screen_spec.md` §0)

- **헤더 1줄**: 로고(`On도마켓` / "동대문 도매 직거래") · `주문 내역` 링크 · 통합 검색 입력(480px) ·
  찜 · 장바구니(뱃지) · 계정 드롭다운.
- **계정 드롭다운 7항목**: 주문 내역 / 미송 대기 현황 / 거래처 관리 / 찜 목록 / 정산 · 미수 / 설정 / 로그아웃.
  §6-5 결함(정산·설정 화면에서 `설정` 누락)은 **고쳐서** 전 화면 동일하게 만든다.
- **카테고리 바**: 전체 · 상의 · 하의 · 아우터 · 원피스·세트 · 신발 · 가방 · 액세서리.
  **홈과 도매처 홈에만** 붙는다.
- **헤더 아이콘은 채팅만 있다**(06a #297, 배지 = 안 읽은 메시지 합). 알림 종은 06b(#304~#306)에서 붙는다. 그 밖의 아이콘은 만들지 않는다 — 필요하면 열린 질문으로 올린다.
- 계정 4화면(로그인·회원가입·승인 대기·승인 거절)에는 셸이 없다. 가운데 정렬 단일 카드다.

## 6. 소매 도메인 요약 (glossary + retail_screen_spec)

- **옵션 = 색상 × 사이즈.** 무늬 축은 폐기됐다. 장바구니·주문·장끼 전부 이 단위다.
- **미송 = SKU 단위**, **도매처가 주문을 확정할 때** 생긴다(RT-59). 소매는 만들지 못한다.
- **미수 = 출고 시점**에 생긴다(RT-64). 원장은 출고 `+` / 입금 `−`.
- **장끼(거래명세서)는 시스템이 자동 발행**하고 **수정 불가·재출력만** 된다. 번호는 `JG-YYYYMMDD-NNN`.
- **수령 2종**: 직접 수령 / 사입삼촌 방문. **택배 없음.** 표준어는 `사입삼촌`(붙여 씀).
- **결제 2종**: **`현금` / `계좌 이체`.** 입금 확인은 도매처가 건별 수동.
  ⚠️ `retail_screen_spec.md` RT-23·RT-34·RT-36은 `현장 결제`로 적혀 있으나 **2026-08-31 게이트 D2로 폐기됐다** —
  도매 주문 탭 게이트 Q4(2026-08-24 승인)와 `glossary` S1(`현금`/`CASH`)을 따른다. 사양 문서는 아직 미반영이다.
- **판매가능 = 현재고 − 주문처리중 − 미송대기.** 소매에는 `재고 소진 · 미송 주문 가능` 배지로만 노출된다
  (수치를 줄지 여부는 §5-10 미결정 — **수치를 지어내지 않는다**).
- **주문 상한은 SKU 하나당** 1회 상한이다(G13). 화면 문구도 그렇게 쓴다.
- 가입은 **운영자 승인제(ST-303)**: 신청 완료 → 심사 중 → 승인 완료. 거절 시 사유 + 재신청.
- 시즌 종료 = 노출 중단·주문 불가. `게시 내림`은 게시글이 내려간 것 — 주문 버튼이 잠긴다.
