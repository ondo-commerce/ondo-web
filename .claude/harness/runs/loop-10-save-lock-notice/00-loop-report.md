## 문제와 다음 회차에 바꿀 것
1. **개발 에이전트가 API 네트워크 오류로 끊기면 다음 사용자 턴까지 멈춘다.** 커밋 ②~④는 돼 있었고 ⑤만 남았는데 20시간 멈춤. 오케스트레이터가 완료 알림 대신 "실패" 알림을 받으면 즉시 같은 에이전트를 SendMessage로 재개하는 걸 기본 절차로(이번엔 사용자 턴 뒤 재개). 끊긴 뒤 실작업 시간 측정이 불가 → 02-dev에 커밋 시각(`git log --format=%ci`)으로 재구성.
2. Codex 기획 비판이 중국어로 답했다. 프롬프트 첫 줄에 "한국어로 답하라"를 넣으니 코드 리뷰부터는 한국어. 기본 문구로.
3. 메타 리뷰를 개발 ⑤(e2e)와 병렬로 ①~④에 먼저 돌리고 결과를 ⑤에 바로 넣어 수정 라운드를 하나 줄였다(M1 M2). 다음 회차 기본: 앱 코드 커밋이 끝나면 e2e 커밋을 기다리지 않고 메타 1차.
4. `bash create-issues.sh`는 auto mode 분류기가 외부 쓰기로 막았다. gh 두 줄을 직접 실행하면 통과. 스크립트는 문서로만 두고 실행은 gh 직접.
5. 다른 세션의 커밋(docs 4919248)이 회차 브랜치 위에 올라왔다. push 전 `git log origin/dev..HEAD`에서 이슈 번호 없는 커밋을 확인하는 줄을 stage 7 체크리스트에. 떼어 둔 브랜치 `docs-harness-ai-priority`(미푸시)는 사용자 몫.
6. QA가 띄운 dev 서버를 QA 자신이 못 끈다(TaskStop 없음, kill 금지). QA 브리프에 "서버는 오케스트레이터가 끈다, 끝날 때 task id를 보고"를 기본 문구로.
7. 기획 §3의 뗄 후보가 회차 고유 위험(S2-6 재저장)을 먼저 떼려 했다(Codex 4-4). 브리프에 "뗄 순서는 중복 장면 → 낮은 우선순위 Story → 회차 고유 위험은 마지막".
8. 변이 생존 2(V4 V5)가 둘 다 "문구·GET이 다른 경로에서 다시 생기는가"였다. 기획 §6에 "같은 상태를 두 경로가 바꾸면(업로드 401과 저장 401, 저장 도중과 저장 뒤) 교차 장면 e2e 1"을 기본 AC 규칙으로.
