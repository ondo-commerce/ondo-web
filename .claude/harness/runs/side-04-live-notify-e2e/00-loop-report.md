## 문제(프로세스가 막힌 곳)와 다음 회차에 바꿀 것
1. 기존 실서버 시험이 반복 실행에서 거짓 통과하고 있었다. #422에서 채팅 답은 응답 id로 특정했지만 도매 종 확인은 그대로 남아 있었다. 실서버 spec 브리프 기본 규칙에 "화면 라벨이 달라졌는지가 아니라 이번 요청이 만든 행의 id"를 넣는다.
2. 메타 리뷰가 2라운드 모두 보류였다. 지적 대부분이 격리 DB에서는 일어나지 않는 동시성 조건이었다. 실서버 시험 회차는 브리프에 "격리 DB 전제, 동시 활동 없음"을 먼저 적어 Codex에 넘긴다.
3. QA 변이 검사는 첫 커밋에서만 돌았다. 수정 커밋 뒤 변이 재실행을 회차 규칙에 넣을지 정해야 한다.
4. 실서버 설정(`playwright.live.config.ts`)은 시험이 실패하면 trace에 로그인 입력값을 남긴다(QA 지적, 이번 diff 밖). `test-results/`는 gitignore지만 public 설정처럼 trace를 끄는 편이 낫다. 이슈로 올리지 않았다.
5. 가짜 서버 spec 여러 개(`e2e/loop-08-chat-polish/helpers.ts` 등)와 서버 레포 시드 주석에 시드 계정 공용 비밀번호가 평문으로 있다(개발 에이전트 지적). 레포가 public이다. 사람 결정 사항.
6. 시드의 옵션 3003 입고일이 2026-11-20이라 그 뒤에는 미송 문의 자동 답이 "입고 예정일이 지났어요"로 바뀐다. 시험은 순서를 바꿔 막았지만 발표 날 시연 데이터는 따로 확인해야 한다.
7. 게이트를 사용자 승인 없이 거부권 모드로 넘겼다. 결정 5줄은 사용자가 뒤집을 수 있다.
