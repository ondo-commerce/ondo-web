## 문제와 다음 회차에 바꿀 것
1. **dev 서버가 떠 있을 때 `pnpm build`를 돌리면 `.next`가 덮여 서버가 묵은 코드를 낸다.** 수정 라운드의 변이 첫 결과가 이 때문에 틀렸다(버리고 재실행). 브리프 공통 규칙에 "4종은 서버를 끈 뒤" 한 줄.
2. loop-10 10-Q2를 "부하 흔들림"으로 accept한 게 틀렸다(단독 재실행 통과 1회로 판단). 같은 spec이 다음 회차에서 단독 실패. 규칙: 전체 e2e 실패를 부하로 분류하려면 단독 3회 통과가 조건. 이번 진단으로 와이어프레임 측정 spec의 글꼴 로딩 의존을 찾아 고침(#412).
3. QA가 띄운 서버를 QA가 못 끈다(두 회차 연속). ondo-qa에 TaskStop이 없다 → QA 브리프 기본 문구 "서버 task id를 보고에 적는다, 오케스트레이터가 끈다"(이번엔 그렇게 함).
4. QA가 e2e 대기에 `until` busy loop를 4개 겹쳐 띄워 부하를 올렸다. 브리프에 "대기 루프는 한 번에 하나, `caffeinate -w`".
5. 하네스 규칙이 회차 중간에 바뀌었다(우선순위, sev 기준, decisions.md). dev·QA 브리프는 변경 전 판으로 나갔고 메타 2차·PR 본문부터 적용. 다음 회차는 브리프 머리에 우선순위 네 줄을 넣는다(brief 템플릿).
6. 변이 m4 생존이 "주석이 틀렸다"로 끝났다. 코드 주석이 Strict Mode 동작을 추측으로 적은 것 → 동작 근거 주석은 unit이나 e2e 이름을 같이 적게(브리프 코드 규칙).
7. auto mode 분류기가 `gh pr create`를 두 번 막았다(docs 브랜치, 사용자 커밋). #411 #413 #414는 통과. 사용자 커밋을 하네스가 PR로 올리는 건 사용자 몫으로 둔다.
