# ADR-0002: API 타입은 OpenAPI 코드젠으로 생성하고, MSW로 백엔드 의존성을 끊는다

- **Status**: Accepted
- **Date**: 2026-08-03
- **Decider**: Frontend 담당 (FE 구현 방식은 단독 결정 / `openapi.yaml` 유지는 BE 협조 필요)
- **관련**: [05 API 계약](../05-api-contract.md), ADR-0001

## 맥락

- FE 1명, BE 2명, 6개월. FE는 두 앱을 혼자 만든다.
- 화면 개발이 API 완성에 직렬로 묶이면 **FE가 대기하는 시간만큼 일정이 그대로 밀린다.** 1명이라 병렬로 다른 화면을 파는 것도 한계가 있다.
- 동시에, API 응답 타입을 손으로 선언하면 스펙 변경 시 **컴파일이 통과하고 런타임에 터진다.** 이게 통합 막판에 몰리면 가장 비싼 버그가 된다.
- 백엔드 구현·스펙 작성은 내 담당이 아니므로, **내가 통제할 수 있는 건 "받은 스펙을 어떻게 소비하느냐"뿐이다.**

## 결정

**`openapi.yaml`(BE 레포 소유)을 단일 진실 원본으로 삼고, FE는 두 가지를 한다.**

1. **타입 코드젠**: `openapi-typescript`로 `packages/api/src/generated/schema.d.ts` 생성.
   - 생성물을 **커밋**한다 (BE 서버 없이 빌드 가능 + PR diff에서 API 변경이 보임)
   - CI에서 **drift 체크** — 재생성 결과가 커밋본과 다르면 실패
   - 도메인 타입을 손으로 선언하는 것을 금지한다
2. **MSW 목킹**: 목 핸들러가 **생성된 타입을 사용**한다.
   - 스펙이 바뀌면 목이 컴파일 에러를 낸다 → 목이 거짓말을 못 한다
   - `NEXT_PUBLIC_API_MOCK` 스위치로 켜고 끄며, **실서버 연동 후에도 제거하지 않는다**
   - 성공 케이스뿐 아니라 **에러 케이스 핸들러도 만든다**

## 대안

### A. BE 완성 후 연동 (목킹 없음)
- 장점: 이중 관리(목 + 실서버) 비용이 없다
- 단점: FE가 BE 일정에 완전히 종속. 에러/빈 상태 UI를 막판에 처음 확인하게 됨
- 탈락 이유: **6개월 일정에서 FE 1명이 2주만 대기해도 회복 불가.** 가장 큰 리스크

### B. 타입을 손으로 선언 + 목 JSON 파일
- 장점: 초기 도입 비용 0, BE 스펙이 없어도 시작 가능
- 단점: 스펙 변경이 타입에 반영되지 않아 **컴파일러가 아무것도 못 잡는다.** 목 JSON은 실제 응답과 조용히 어긋난다
- 탈락 이유: 리뷰어 없는 1인 개발에서 컴파일러가 유일한 방어선인데, 그 방어선을 스스로 끄는 선택

### C. tRPC / GraphQL Codegen
- 장점: 타입 안전성이 더 강하다
- 단점: tRPC는 BE가 TypeScript여야 하고, GraphQL은 BE 2명이 스키마·리졸버·N+1까지 감당해야 함
- 탈락 이유: **BE 스택에 대한 결정권이 나에게 없다.** FE 사정으로 BE 아키텍처를 바꾸자고 요구하는 건 비용 대비 실현성이 낮다

## 결과

**좋아지는 것**
- BE 진행 상황과 무관하게 화면 개발이 진행된다 (프로젝트 최대 리스크 제거)
- API 스펙 변경 시 **`tsc`가 영향 범위를 알려준다.** 손으로 찾지 않는다
- 에러·빈 상태 UI를 초기부터 개발·확인할 수 있다
- BE 장애/점검 중에도 FE 작업이 멈추지 않는다

**나빠지는 것 / 감수하는 비용**
- MSW 핸들러를 **유지보수해야 한다.** 실서버 연동 PR마다 목도 갱신 (PR 템플릿에 체크 항목으로 강제)
- 목과 실서버가 어긋날 여지는 남는다 — 타입은 같아도 **동작(정렬 순서, 페이징 경계, 지연)은 다를 수 있다.** 통합 시 한 번은 반드시 확인 필요
- `openapi.yaml` 품질에 의존한다. BE가 스펙을 갱신하지 않으면 코드젠도 거짓말이 된다
- 생성 파일을 커밋하므로 PR diff가 가끔 커진다

**이 결정을 되돌려야 하는 신호**
- BE가 `openapi.yaml`을 유지하지 않아 스펙이 3주 이상 실제와 어긋날 때 → 스펙 자동 생성(FastAPI/springdoc) 강제 또는 계약 테스트 도입 검토
- MSW 유지 비용이 주당 2시간을 넘을 때 → 스테이징 서버 상시 사용으로 전환하고 목은 E2E 전용으로 축소
