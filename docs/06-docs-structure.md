# 06. 문서 구조 (Notion / GitHub Docs) · P1

## 분리 원칙 한 줄

> **코드와 함께 변하는 것은 GitHub, 사람과 함께 변하는 것은 Notion.**

같은 내용을 두 곳에 두지 않는다. 이중 관리는 예외 없이 한쪽이 썩는다.
한쪽에 원본을 두고 다른 쪽에는 **링크만** 건다.

| 판단 기준 | 어디에 |
|---|---|
| 이 문서는 PR과 함께 수정되어야 하나? | GitHub |
| 비개발자(멘토·기획·디자인)가 봐야 하나? | Notion |
| 코드 예시가 들어가나? | GitHub |
| 회의·일정·의사결정 맥락인가? | Notion |

**루트 필수 3개**
| 파일 | 내용 | 분량 |
|---|---|---|
| `README.md` | 프로젝트 1줄 소개 / 실행 3줄 / 스크립트 표 / docs 링크 | 1페이지 |
| `CONTRIBUTING.md` | 브랜치·커밋·PR 규칙 요약. **새 사람이 이것만 읽고 PR을 낼 수 있어야 함** | 1페이지 |
| `.env.example` | 필요한 환경변수 전부 + 주석 | — |

**README 스크립트 표 (그대로 사용)**

| 명령 | 설명 |
|---|---|
| `pnpm dev:wholesale` | 도매 앱 개발 서버 (:3000) |
| `pnpm dev:retail` | 소매 앱 개발 서버 (:3001) |
| `pnpm codegen` | openapi → 타입 재생성 |
| `pnpm typecheck` | 전체 타입 검사 |
| `pnpm lint` / `pnpm format` | 린트 / 포맷 |

## Notion

팀 전체(멘토·BE·디자인 포함)가 보는 공간. **페이지 5개면 충분하다.**

```
📁 onDo
├── 🏠 홈 — 팀 대시보드
│     · 이번 주 목표 / 각자 진행 상황 / 주요 링크(레포·Vercel·Figma·API 문서)
│
├── 📋 기획 · MVP 정의
│     · MVP 범위 (In / Out 명시)
│     · 화면 목록 + 우선순위
│     · 유저 플로우
│     · 용어 사전 ★  (도매/소매 도메인 용어 — 이게 없으면 변수명이 사람마다 달라진다)
│
├── 🗓 일정 · 회의
│     · 마일스톤 (중간발표·최종발표 역산)
│     · 주간 회의록 (템플릿 고정)
│     · 결정 대기 항목 (Blocked 리스트)
│
├── 🔌 API · 데이터
│     · openapi.yaml 링크 (원본은 BE 레포)
│     · 에러 코드 → 사용자 문구 매핑표 ★ (FE·BE 공동 관리)
│     · 상태값(enum) 사전: 주문상태·상품상태
│
└── 🎨 디자인
      · Figma 링크
      · 디자인 토큰 ↔ Tailwind 토큰 매핑표 ★
      · 컴포넌트 인벤토리 (Figma 컴포넌트 ↔ packages/ui 대응)
```

★ 표시 3개가 **FE 입장에서 실제로 매일 쓰는 문서**다. 나머지는 안 봐도 일이 돌아간다.

### 용어 사전을 P1로 두는 이유

도매/소매 도메인은 용어가 갈린다. "상품 / 품목 / SKU / 옵션", "발주 / 주문 / 오더".
이걸 안 정하면 **BE는 `item`, FE는 `product`, 기획서는 `품목`**이 되고, 6개월 뒤 매핑 코드가 곳곳에 생긴다.

| 한국어 | 코드 표기 | 정의 | 비고 |
|---|---|---|---|
| 상품 | `product` | 판매 단위 | |
| 색상·무늬 | `variant` | 상품의 하위 구분 | 사진 1장이 붙는 단위 |
| 사이즈 | `size` | variant의 하위 | UI에 노출 여부 별도 결정 |
| 주문 | `order` | 소매 → 도매 | |
| 발주 | `purchaseOrder` | 도매 → 공장 | `order`와 혼용 금지 |

→ 이 표를 Notion에 두고, **API 필드명·컴포넌트명이 여기서 나온다.**

### 회의록 템플릿 (고정)

```
날짜 / 참석자
1. 지난주 액션 아이템 체크
2. 각자 진행 상황 (3줄씩)
3. 논의
4. 결정 사항        ← 되돌리기 비싼 결정이면 ADR로 옮긴다
5. 액션 아이템 (담당자 + 기한)
6. 막힌 것 (Blocked)
```
**4번에서 나온 아키텍처 결정은 반드시 ADR로 옮긴다.** 회의록에만 있으면 3개월 뒤 아무도 못 찾는다.

## 안티패턴 (하지 말 것)

| ❌ | 왜 |
|---|---|
| 컨벤션을 Notion에도 복사 | 코드 리뷰 중 규칙을 고칠 때 GitHub만 고치고 Notion은 방치됨 |
| API 명세를 Notion 표로 관리 | openapi.yaml과 100% 어긋난다. 링크만 걸 것 |
| Notion에 코드 블록으로 컴포넌트 사용법 | 코드가 바뀌면 즉시 거짓말이 됨. Storybook 또는 레포로 |
| 문서를 위한 문서 (아키텍처 개요 20페이지) | 6개월 프로젝트에서 아무도 안 읽는다 |
| 회의록에만 있는 결정 | 검색이 안 됨 → ADR로 |
